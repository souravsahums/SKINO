# HamiltonianNN: FNO3D against CKINO3D on a 3-D elastic-lattice simulator

A side study, separate from the paper (see the [main README](../README.md)). Two neural operators are trained on trajectories of the project's own 3-D elastic-lattice simulator [`elm1.py`](elm1.py) and compared on one-step accuracy and on an autoregressive rollout:

- **FNO3D**, a Fourier Neural Operator written from scratch in [`fno_model.py`](fno_model.py): 5,902,302 parameters.
- **CKINO3D**, the Chebyshev kernel-integral operator, re-used from [`ckino/nd.py`](../ckino/nd.py): 8,818 parameters.

Both use the same data, residual learning, optimiser and train/validation split. The training objectives differ: FNO3D is trained on one step, CKINO3D with a push-forward curriculum. An FNO3D trained with the same curriculum is part of the study.

The comparison is **not capacity-matched** (the parameter counts differ by 669×), uses **one seed**, and has **one test trajectory** (three trajectories in all, two for training). It reports what these two configurations do on this simulator. It does not show which architecture is better, and it does not isolate which component of CKINO3D is responsible for the differences. CKINO3D's block is volume-preserving but not symplectic (paper §4.1 and Appendix A), and the study does not use the paper's SA-Cheb construction.

The full write-up is [`comparative_study.md`](comparative_study.md). Its description of CKINO3D's update as symplectic does not match the paper; where the two differ, the paper is authoritative.

## Quick start

```powershell
# Anaconda Python 3.13.5; PyTorch 2.12.0+cpu, numba 0.61 (simulator), ffmpeg (video).
$env:KMP_DUPLICATE_LIB_OK = "TRUE"   # OpenMP runtime is shared between MKL and matplotlib on Windows

python generate_data.py --n-runs 3 --n-steps 600 --save-every 2 --output-dir output2
# FNO3D: one-step training, 25 epochs.
python train.py --only fno --epochs 25 --batch-size 8 --stride 2 --burn-in 20
# CKINO3D: K = [1, 4] push-forward curriculum, 24 epochs (the option is spelled `skino`).
python train.py --only skino --epochs 24 --batch-size 8 --stride 2 --burn-in 20 --skino-unroll-schedule 1 4
# Roll out from the training burn-in step, so the network starts from an in-distribution state.
python rollout.py --test-run 2 --start-step 20 --video-stride 2 --fps 18
python analyze_rollout.py
```

[`run_all.py`](run_all.py) runs the same stages with the scripts' defaults. Its FNO3D stage is the one above, but its CKINO3D stage differs from the reported one: it uses the default curriculum (`--skino-unroll-schedule 1 4 8`) rather than `1 4`, and 25 epochs rather than 24. Use the explicit commands to follow the recipe in [`comparative_study.md`](comparative_study.md) §3.

`output2/` (simulator output), `models/` (checkpoints and logs) and `video/` (the comparison animation, rendered by `rollout.py` with ffmpeg) are generated by these commands and are not in the repository.

## Results

From [`results/rollout_summary.md`](results/rollout_summary.md) and [`comparative_study.md`](comparative_study.md): one seed, test trajectory 2, a rollout of 280 saved states (560 ms) started at saved state 20.

| | FNO3D | CKINO3D |
|---|---:|---:|
| Trainable parameters | 5,902,302 | 8,818 |
| Best one-step validation MSE | 1.64 × 10⁻⁶ | 3.49 × 10⁻⁷ |
| Training wall-clock (CPU) | 391 s (one-step) | 2,383 s (K = [1, 4] curriculum) |
| 280-step rollout wall-clock (CPU) | 23.28 s | 5.65 s |
| Median post-burn-in wMAPE, displacement q | 110.22 % | 101.21 % |
| Median post-burn-in wMAPE, momentum p | 108.13 % | 101.19 % |

- **Neither rollout is accurate.** A zero prediction scores exactly 100 % on wMAPE, $\sum|\hat u-u| / \sum|u|$, and both models' medians are above it.
- **The shapes of the failures differ.** FNO3D's peak displacement stays at its initial value (about 2.06 m) for the whole rollout, because its predicted update is almost zero. CKINO3D's peak decays: the study reports it within about 2× of the true envelope through step 80, and it ends about 20× below it (7.7 mm against 0.15 m at step 280).
- **The curriculum does not transfer to FNO3D.** With the same push-forward curriculum, FNO3D's median displacement wMAPE is 111.32 % and its predicted amplitude decays slowly instead of following the wave ([`comparative_study.md`](comparative_study.md) §4.3).
- **One-step accuracy favours CKINO3D** (3.49 × 10⁻⁷ against 1.64 × 10⁻⁶), with 669× fewer parameters; wall-clock and peak-amplitude figures are single CPU measurements.

[`figures/comparison_frames.png`](figures/comparison_frames.png) is a static contact sheet of the rollout; [`figures/rollout_wmape_log.png`](figures/rollout_wmape_log.png) shows wMAPE per step on a log scale.

## Protocol

1. **Push-forward curriculum for CKINO3D.** One-step training for 12 epochs ($K=1$), then 4-step unrolled MSE for 12 epochs ($K=4$), which penalises the error accumulation that one-step training does not see. A $K=8$ phase was tried and collapsed (the output went to zero), so it was dropped; `train.py` still defaults to the schedule $1, 4, 8$, hence `--skino-unroll-schedule 1 4`.
2. **Rollouts start in distribution.** The simulator's first 20 saved states are the source-firing transient (zero to peak amplitude). Training uses `burn_in=20`, so the network never sees the source kick and cannot reproduce it from a zero state. Rollouts therefore start at saved state 20 (`--start-step 20`, the default); `--start-step 0` gives the zero-state rollout.
